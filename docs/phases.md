# 分期计划

> 原则：先把权限、审计、版本、配置中心做成公共底座，再叠业务模块。AI 和聊天不要抢在权限底座之前。

## 开发顺序建议

1. 配置中心 → 账号/权限 → 字段权限 → 审批引擎。
2. 员工/组织/岗位履历 → 自定义属性 → 审计/版本。
3. 项目/成员 → 文档基础 → 通知。
4. 导入 → 审批 UI → 任务/里程碑/进度 → 文档完整权限。
5. AI（先花名册解析，再文档问答/人员问答/操作指引）。
6. 聊天（基础先上，高级后置）。
7. 搜索/预览/报表/性能。

## 风险

- 字段级权限 + 审批 + 审计是横切能力，必须最先做，否则各模块重复实现。
- 自定义属性纯 EAV 会影响性能；可搜索字段要建索引/同步 ES。
- AI 文档问答必须先做权限过滤，不能先做问答再补权限。
- 聊天“阅后即焚/防撤回”无法防截图，需求要写清边界。
- 文档硬删除与备份/审计留存的边界要提前告知使用方。
